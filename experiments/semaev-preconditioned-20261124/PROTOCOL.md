# Exact affine preconditioning: significance target and frozen comparison

Frozen 24 November 2026 before candidate implementation/timing. Local CPU only.

## Scope and target

Improve the corrected binary PDP GB path of PR #55. No new ECDLP exponent
or novel root-finding algorithm is claimed. Existing LRF is a comparator,
not a new contribution. Primary candidate: original S4 with trace-aware
affine preconditioning. Preconditioned split is a prespecified secondary
candidate. Do not select the faster candidate independently for each test case.

Significance target: at least 2x geometric-mean reduction in charged
setup+preprocessing+GB+FGLM/recovery time against the lower envelope of the
original and split baseline medians on the same cases. Check exact outputs.
Report the 33 prior cases separately from the new held-out cases; the primary
candidate is fixed before observing either timing set. Keep every case,
failure and timeout; no gain is assigned to an unfinished baseline pair.

## Instances

Reuse all 33 frozen inputs from semaev-matched-20261124, without changing
their oracle, targets, membership constraints or variable ordering. Add a
held-out grid (n,ell)=(7,3),(9,3),(11,3), seeds 3,4. Use exactly the prior
seeded curve/target selection rule: seeded bit a, uniform nonzero b, V the
monomial basis span; first shuffled rational target with a solution and first
without, recording unavailable categories. No performance tuning on held-out
cases. Generate inputs and commit their hashes before the benchmark.

## Candidate

1. Build the same Boolean system and membership equations as the baseline.
2. Add trace(x1+x2+x3+r)=0 for the original PDP. For the finite split, use
   trace(x1+x2+u+a)=trace(u+x3+r+a)=0. Prove validity from the rational curve
   addition law and the complete PDP correspondence, including degeneracies.
3. Echelonize the row span by decreasing Boolean monomial degree, extract
   affine rows and substitute pivot variables exactly in the Boolean ring.
   Repeat to a fixed point, retaining an affine recovery map. A constant 1
   proves inconsistency; no residual equations means all remaining bits free.
4. Apply the same SymPy 1.14.0 Buchberger/grevlex backend to the residual
   ordinary GF(2) system with Boolean equations, then exact recovery.

No search, tuple oracle or enumeration enters preprocessing. Enumeration
only recovers the remaining Boolean solutions from the lex basis (as in the
baseline), or expands an unconstrained residual cube. Recovery of eliminated
bits and the split infinity branch is charged.

## Measurement and controls

Methods: original, split, original_preconditioned, split_preconditioned,
and existing LRF plus the same explicit infinity correction. Use three fresh
processes per case/method, deterministically rotated order, one CPU thread.
Charge input construction, preprocessing, solving and complete tuple recovery.
Separate oracle verification, imports/startup, and cold C-kernel compilation.
Expand LRF point multisets into the same ordered x-coordinate tuple set.

Shared input-construction clarification, before timings: replace the prior
O(|k|²) point scan for membership by exact lift tests on V, for every GB
method equally. Check byte-for-byte equality of the generated equations with
the audited builder. Target selection uses the identical sorted rational-point
list, generated by lift tests instead of scanning both coordinates. Neither
change is counted as a preprocessing gain over the fresh baselines.

10-second GB-call cap; 40-second process cap; 1800-second whole-run cap.
Keep errors/timeouts/unrun cases. Record every repetition and per-case medians,
geometric-mean speedup, win/loss counts, candidate reduction dimensions and
preprocessing work. Report against each GB baseline, their lower envelope,
and LRF. Identify baseline/candidate cases solved by preprocessing alone.

Independently exhaustively check generic affine preprocessing on random small
Boolean systems and trace-augmented PDP systems against point enumeration.
Retain exact correspondence proofs and source/input/protocol hashes. Run the
repository tests and saved-publication checks before marking the PR ready.
